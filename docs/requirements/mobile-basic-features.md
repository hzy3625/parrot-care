# Android 移动端核心功能设计与开发计划

## 1. 系统目标

移动端的目标不是医疗诊断，而是帮助鹦鹉饲养者建立每只鹦鹉自己的日常声音基线，在发现异常时快速记录并得到可解释的变化提示：

```text
建立鹦鹉档案
  -> 定期录制日常声音，积累个体基线
  -> 发现异常时录制 / 导入声音
  -> 在本机与同一只鹦鹉最近的基线对比
  -> 查看响度、声音活跃占比和峰值变化
  -> 结合无音频观察、类别、状态和备注持续复盘
  -> 导出备份，在另一台手机导入
```

0.2.1 已完成“记录、管理、迁移”的基础闭环并通过真机验证。0.3.0 开始回归产品核心：先用个体基线和可解释的本地音频特征提供变化提示，后续再用真实数据训练的 ML 模型增强分类能力。

## 2. 使用场景

### 2.1 日常基线记录

用户定期录制鹦鹉正常状态下的叫声，作为后续对比素材。

- 选择鹦鹉。
- 录制声音。
- 试听后保存为“日常基线”。
- 类别选择“正常鸣叫”或“待确认录音”。
- 填写备注，例如“早上进食后正常叫声”。

### 2.2 异常声音记录

用户发现持续尖叫、夜间惊飞、异常安静等情况时，快速记录声音。

- 选择鹦鹉。
- 录制或导入已有音频。
- 保存为“异常观察”。
- 人工选择类别和状态。
- 后续在详情页更新为“观察中”“已处理”或“已排除”。

### 2.3 无音频健康观察

部分场景没有音频，但仍需要记录，例如啄羽、精神差、食欲变化。

- 选择鹦鹉。
- 新建“观察记录”。
- 类别选择“啄羽行为”“异常安静”或“待确认录音”。
- 填写备注。
- 后续修改状态和备注。

### 2.4 多只鹦鹉管理

一个用户可能同时饲养多只鹦鹉。所有记录必须归属到具体鹦鹉，避免混淆。

- 创建多个鹦鹉档案。
- 录制时选择当前鹦鹉。
- 记录列表按鹦鹉筛选。

### 2.5 换机和数据备份

移动端核心数据存储在本机。用户换手机时，需要通过文件完成迁移。

- 旧手机导出 ZIP 备份。
- 新手机导入 ZIP。
- 导入后保留鹦鹉档案、事件记录、音频文件、类别、用途、状态和备注。

## 3. 范围与边界

### 3.1 当前阶段包含

- 原生 Android Java/XML。
- 本地鹦鹉档案。
- 本地录音。
- 本地音频导入。
- 无音频观察记录。
- 人工类别、用途、状态和备注。
- 本地列表、详情、播放、修改和删除。
- 本地 ZIP 备份导出和导入。
- 同一只鹦鹉的日常声音基线统计。
- 本地音频特征提取和基线变化对比。
- 离线可用。

### 3.2 当前阶段不包含

- ML 训练、端侧模型和自动声音分类。
- 服务端分析、账号登录和云同步。
- 后台持续监听、定时任务和异常通知。
- 医疗诊断或自动健康结论。
- iOS、WebView 或跨平台运行时。

所有核心功能必须在无网络、未启动 API、未登录账号的情况下工作。

  - `apps/mobile/android/scripts/device-smoke-test.sh`

### 4.3 0.2.1 真机验证结果

用户已在 Android 手机上安装 0.2.1，并确认基础功能可正常使用。录音、导入、保存、记录库、详情和本地数据流程已通过基础真机验证。

权限拒绝、损坏备份、空间不足、旋转中断等异常和边界场景仍需要后续专项回归，不影响进入核心能力开发。

### 4.4 0.3.0 核心能力

- 首页显示当前鹦鹉的日常基线数量。
- 提供独立的“录制日常基线”入口。
- 异常声音详情提供“与日常基线对比”。
- 完全在手机本地解码音频并提取：
  - 整体响度（dBFS）。
  - 峰值（dBFS）。
  - 声音活跃占比。
- 使用同一只鹦鹉最近最多 5 条有效基线计算平均参考值。
- 输出“接近日常基线”“有一定变化”或“变化明显”，并展示具体差异。
- 基线不足时明确提示，不生成伪结论。
- 结果只作为声音变化线索，不作为疾病识别或医疗诊断。
- APK 版本升级为 `0.3.0`。

## 5. 功能清单

### 5.1 首页

- 高频入口：
  - 记录异常声音。
  - 导入音频。
  - 新建观察。
- 核心入口：
  - 查看当前鹦鹉的日常基线数量。
  - 录制日常基线。
- 常用入口：
  - 最近 5 条记录。
  - 查看全部记录。
- 低频入口：
  - 鹦鹉档案。
  - 导出备份。
  - 导入备份。

### 5.2 鹦鹉档案

字段：

- 名称，必填。
- 品种，可选。
- 出生日期或年龄，可选。
- 备注，可选。

能力：

- 新建鹦鹉档案。
- 修改档案。
- 切换当前鹦鹉。
- 记录列表按鹦鹉筛选。

暂不提供删除档案，避免误删关联记录。后续可增加“归档”。

### 5.3 录音

- 点击录音时申请麦克风权限。
- 显示正在录音状态。
- 动态显示录音时长。
- 支持停止和取消。
- 录音停止后进入保存表单。
- 保存前可试听/暂停。
- 支持重新录制。
- 过短、空文件或录制失败时不创建数据库记录。
- 应用进入后台时停止并丢弃尚未确认的录音。

### 5.4 导入音频

- 使用系统文件选择器选择 `audio/*`。
- 将选中文件复制到 App 私有目录。
- 导入后进入与录音相同的保存表单。
- 导入前校验文件大小和可识别时长。
- 非音频、空文件、过短文件或无法识别文件给出错误提示。

### 5.5 新建观察

- 不申请麦克风权限。
- 不要求音频文件。
- 必须选择鹦鹉、用途、类别和状态。
- 支持备注。
- 保存后进入记录详情。

### 5.6 记录保存

记录用途：

- `baseline`：日常基线。
- `abnormal`：异常观察。
- `manual`：无音频观察。

状态：

- `pending`：待处理。
- `reviewing`：观察中。
- `resolved`：已处理。
- `false_positive`：已排除。

人工类别：

- 正常鸣叫 `normal_chirp`
- 持续尖叫 `scream`
- 夜间惊飞 `night_fright`
- 啄羽行为 `plucking`
- 异常安静 `silence`
- 待确认录音 `unclassified`

### 5.7 记录库

- 默认按创建时间倒序。
- 显示鹦鹉、类别、用途、状态、时间和时长。
- 无音频观察显示“无音频”。
- 支持鹦鹉、类别、用途和状态筛选。
- 点击记录进入详情。

### 5.8 记录详情

- 显示鹦鹉、类别、用途、状态、创建时间、来源、时长和备注。
- 有音频时支持播放/暂停。
- 异常音频支持与同一只鹦鹉的日常基线对比。
- 日常基线明确标识其用途。
- 无音频时不显示播放按钮。
- 支持修改鹦鹉、类别、用途、状态和备注。
- 支持删除记录。
- 删除音频记录时同步删除私有目录音频文件。
- 音频缺失时详情仍可打开并允许删除。

### 5.9 数据导出/导入

- 导出 ZIP 备份。
- 备份包含：
  - `version.txt`
  - `parrots.tsv`
  - `events.tsv`
  - `audio/`
- 不包含账号凭据、设备标识、API Token 或未来云同步凭据。
- 导入时使用新 UUID 处理冲突，不覆盖现有记录。
- 单条失败不影响已有本地数据。

## 6. 当前代码结构

当前为了保持移动端最小化，页面仍集中在一个 `MainActivity` 中，通过原生 View 动态切换页面，不引入 AndroidX Navigation、Fragment、Compose 或第三方 UI 框架。

```text
com.parrotcare.mobile/
  MainActivity.java
  audio/
    AudioRecorder.java
    AudioPlayer.java
    AudioFeatureExtractor.java
    AudioFeatures.java
    BaselineComparison.java
  data/
    LocalStore.java
    AudioFileStore.java
    BackupStore.java
    SimpleFileProvider.java
```

后续如果页面继续增多，可以再拆分为：

```text
parrot/ParrotActivity.java
record/RecordActivity.java
observation/ObservationActivity.java
library/LibraryActivity.java
detail/DetailActivity.java
data/DataActivity.java
model/*.java
```

拆分前提：功能已经稳定，且拆分不会引入 AndroidX 或额外依赖。

## 7. 本地数据模型

### 7.1 鹦鹉表

```sql
CREATE TABLE parrots (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    species TEXT NOT NULL DEFAULT '',
    birthday TEXT NOT NULL DEFAULT '',
    note TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

### 7.2 事件表

```sql
CREATE TABLE events (
    id TEXT PRIMARY KEY,
    parrot_id TEXT NOT NULL,
    category_id TEXT NOT NULL,
    status TEXT NOT NULL,
    purpose TEXT NOT NULL,
    audio_path TEXT,
    source TEXT NOT NULL,
    duration_ms INTEGER NOT NULL DEFAULT 0,
    note TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

字段约束：

- `purpose` 只允许 `baseline`、`abnormal`、`manual`。
- `source` 只允许 `recording`、`import`、`manual`。
- `source=manual` 时 `audio_path` 可以为空，`duration_ms=0`。
- `source=recording` 或 `source=import` 时 `audio_path` 必须有值。
- 音频文件只放在 `files/audio/`。
- 数据库只保存稳定的应用内相对路径，不保存音频二进制。
- 当前不保存 `confidence`、模型版本或自动风险等级。
- 0.3.0 的音频特征按需在本机计算，不写入数据库，不改变备份格式。
- 旧数据没有 `parrot_id` 时归到“默认鹦鹉”。

## 8. 下一步开发顺序

### 8.1 P0：0.3.0 核心闭环真机验证

1. 为同一只鹦鹉录制至少 3 条日常基线。
2. 录制一条相似声音，确认结果接近日常基线。
3. 录制一条明显更响或更安静的声音，确认变化指标方向正确。
4. 验证只有 0 条、1 条基线和基线文件损坏时的提示与降级。
5. 验证 M4A、MP3、WAV 在目标手机上的本地解码兼容性。

### 8.2 P0：核心结果可用性

1. 让用户在对比结果页直接补充观察备注和状态。
2. 增加基线录制环境提示，例如距离、位置和环境噪声。
3. 对比结果保存为结构化历史，支持查看变化趋势。
4. 避免重复点击产生重复分析或重复保存。

### 8.3 P1：数据安全加强

1. 备份导入前增加预览：档案数、记录数、音频数。
2. 增强 ZIP 校验和错误报告。
3. 支持重复导入检测，减少重复记录。
4. 支持备份文件校验摘要。

### 8.4 P1：结构整理

1. 将过大的 `MainActivity` 拆分为多个 Activity 或页面控制类。
2. 将 `LocalStore` 内部类拆为独立 model。
3. 增加更明确的用例方法，集中处理文件与数据库一致性。

### 8.5 P2：ML 能力准备

1. 增加“训练可用”标记。
2. 增加“是否确认类别”的人工标注字段。
3. 增加导出训练数据包能力。
4. 后续再考虑 ML 训练和自动分类。

## 10. 完成标准

代码开发完成必须同时满足：

- `make check-android check-structure` 通过。
- `make android-release` 生成版本化 APK。
- APK 不包含第三方运行时、模型、密钥或用户数据。
- 在至少一台 Android 真机完成 P0 全流程测试。
- 验证拒绝权限、离线启动、进程重启和升级保留数据。
- 更新 `apps/mobile/release/android/README.md` 的版本、构建与测试记录。
